# Bounded native-router capabilities

Evidence date: October 26, 2026. Admitted means the runtime allows the explicitly configured contract. Thirteen of the original 23 text choices are now admitted: twelve Claude pairs plus one exact AGY Gemini High pair. All twelve Claude pairs have exact JSON and signed tool-SSE application-handler round trips with synthetic providers. The current local implementation admits the same thirteen original tool choices, with a narrower complete-call Gemini subset. The focused handler run passed **32/32**, and the installed-SDK run passed **18/18** (earlier fifteen plus three AGY cases, with original-schema assertions). The the selected 79-file regression and focused independent acceptance passed. Nonstreaming Gemini execution remains unsupported. Plain-text SSE tests cover representative pairs and an explicit OpenAI fixture, not the complete cross-product of every request option. This does not prove account access, live OAuth interoperability, billed cost or model-selection quality. Saving a profile never runs a provider request.

Ordinary requests retain their existing clamps and effort lists. No global model registry or ordinary effort defaults were changed.

Primary public contracts: [Opus 5.5](https://platform.claude.com/docs/en/models/opus-5-5/overview), [Sonnet 5.5](https://platform.claude.com/docs/en/models/sonnet-5-5/overview), [Haiku 5.5](https://platform.claude.com/docs/en/models/haiku-5-5/overview), [effort and output accounting](https://platform.claude.com/docs/en/build-with-claude/effort), and the separate [Claude Code model configuration](https://code.claude.com/docs/en/model-config). These mutable documents were checked on the evidence date. API-key authentication and subscription OAuth are distinct; documentation does not establish a particular account's entitlement or third-party OAuth compatibility.

The bounded Claude lane sends no sampling controls. Its trusted request scope prevents the legacy formatter from synthesizing temperature 1; it does not delete supplied sampling fields. Explicit or late-injected temperature/top_p/top_k remain visible and are rejected at the final fence. Ordinary requests retain their prior sampling normalization. No client-visible bypass flag was introduced.

Capabilities, context limits, effort support and evidence remain explicit operator profile declarations. A listing, active connection or declaration is not a successful provider test. Unsupported or unknown contracts must not be silently substituted with another model, effort, account or paid provider. The OpenAI API-key lane is separate from the historical pool and is not a substitute for Codex OAuth or AGY. The single AGY Gemini contract below does not admit another AGY model or the separate `antigravity` connection namespace.

## Native selection

The selector receives only currently eligible explicit model-and-effort options. A client-supplied effort is a hard constraint. For example, explicit Medium can offer both Opus Medium and Sonnet Medium; it does not authorize High or Max. Operator task preferences remain unchanged. Confidence is a provider-reported value, not measured correctness or permission.

Two or more eligible options use the configured native decision provider; exactly one uses the existing guarded execution with explicit `sole-eligible` / `no-decision`; zero returns `no-route`. Decision and execution receipts remain separate. Refusal, malformed selection, authentication/access/quota denial, cancellation and queued policy changes cannot authorize an unintended execution or hidden fallback.

Free Zen requires an explicit native `jev-1.13-free` binding and the actual free routing guard. These local fixtures establish no live free-Zen success or quota-reset scope. Existing paid selector contracts remain separate; no paid fallback is introduced.

## Pinned Hermes and installed SDK evidence

The source fixtures execute original request-builder and tool-result fragments from [Hermes commit 749cb638ff43f9ce5333c186a1e4f67d473aa4f2](https://github.com/NousResearch/hermes-agent/tree/749cb638ff43f9ce5333c186a1e4f67d473aa4f2), with its MIT license, byte-level provenance and named collaborators. Whole Hermes modules, CLI configuration, dotenv, authentication and plugin discovery are not executed.

The earlier source-only fixture used an explicit JSON projection; that result did not establish SDK wire behavior. The subsequent [installed SDK fixture](../../tests/integration/decision-hermes-installed-sdk.test.ts) independently passed **15/15** offline cases at the preceding checkpoint using actual OpenAI Python SDK 2.54.0 and HTTPX 0.28.1 on standalone Python 3.12, installed from seventeen exact hash-locked official wheels. Actual SDK serialization, headers, JSON/SSE parsing and tool-call assembly enter the real authenticated handler through a bounded in-memory stdio bridge. It covers explicit Medium/High, pinned tool continuation, terminal denial without SDK retry, cancellation, unknown versus zero cost, and optional effort delegation. There is no socket HTTP server or real provider call. The current installed-SDK run passed **18/18** (the earlier fifteen plus three AGY cases) with strengthened original-schema assertions, natural exit 0 in 41.153 seconds. The three new SDK cases also passed independent acceptance with natural exit 0; the selected 79-file regression passed. This is not whole-repository acceptance. Full pinned Hermes requires Python 3.14 and remains unrun.

Normal Hermes `custom` defaults unset effort to explicit Medium, which remains a hard routing constraint. The new, optional [effort-delegation extension](HERMES_EFFORT_DELEGATION.md) has **22/22** independent source-builder checks. It needs a dedicated exact-target profile and two mandatory pinned source guards; neither is installed. It delegates only the unset default, preserves explicit Medium/High/Off and recovery behavior, and leaves ordinary defaults unchanged. Its default-resolver fragment has a documented web-rendered-source boundary, not a claimed raw whole-module hash. Do not advertise the default Hermes client as automatically delegating effort.

A configured output cap remains required. Tool continuation retains the originating pair and needs fresh admission, explicit continuation-policy membership and required signed replay. See [the tool contract](NATIVE_ROUTER_TOOLS.md). The combined decision/execution deadline remains 30 seconds. Automatic OAuth refresh, full client retry/fallback behavior, broader optional-feature coexistence, recovery/evaluation UX and quality validation remain unfinished. No raw message excerpt is included in the native selector's current task/count metadata.

## Text streaming boundary

The same opt-in application handler now accepts text SSE with exact provider/model/effort and an explicit output cap. Raw provider frames are inspected before ordinary translation; a bounded pull-through wrapper preserves backpressure and independently observes client completion/cancellation. Provider terminal evidence and downstream synthesized completion are kept separate. Decision calls remain non-streaming. See [streaming behavior and tests](NATIVE_ROUTER_STREAMING.md).

The historical pool remains 23 choices with unchanged preferences. Twelve Claude choices have JSON and signed tool-SSE fixtures; representative plain-text SSE coverage is separate. The thirteenth choice is `agy/gemini-3.8-flash-high` at High. Its [guarded transport](../../open-sse/executors/antigravity/bounded.ts) and [actual-handler tests](../../tests/integration/decision-agy-gemini-contract.test.ts) preserve the ready AGY OAuth account/project, exact model, `thinkingLevel: high` and unchanged `maxOutputTokens` up to 65,536. This is an exact local Cloud Code slot contract, not a public Gemini API alias or a verified live entitlement. Plain text SSE needs a nonempty final user turn and keeps tool-looking output as text. The separate opt-in [Gemini complete-call tool contract](NATIVE_ROUTER_GEMINI_TOOLS.md) now handles declared functions and authenticated active-cycle results. It preserves the exact account/model/High/project and each reserved output cap, with original ordered native Part replay. Images and nonstreaming requests remain excluded. Old completed tool cycles before the latest user are screened out before decision selection; the public current-turn signature rule does not prove a private AGY older-history waiver. The truthful application identifier is `OmniRoute-Antigravity/1.0`; client fingerprint compatibility, refresh, bootstrap, alias/recovery routing and credit retries are not enabled.

Ten original choices remain excluded before native selection:

- **Nine Codex OAuth choices:** `gpt-6-luna` Max, plus `gpt-5.6-sol` and `gpt-6-sol` at Medium/High/XHigh/Max. Their native effort vocabulary is source-documented, but the [local executor](../../open-sse/executors/codex.ts) removes output-limit fields. The [pinned official Responses request](https://github.com/openai/codex/blob/970111f6cb62cc02fe36a82ea7d71b37a2889c97/codex-rs/codex-api/src/common.rs#L279) provides no proven generation cap for this existing OAuth contract. This is not a live finding that the remote server rejects every unknown cap field. API-key Responses or a different OAuth flow cannot silently replace it, and Max is not remapped to XHigh.
- **AGY Opus High:** `agy/claude-opus-4-6-thinking` lacks a verified exact fixed-High thinking/output-bound contract for this Cloud Code slot. Product availability does not establish that wire contract. The new Gemini-only guard explicitly excludes it; no generic `agy`/`antigravity` alias grants admission.

The [execution-eligibility fixture](../../tests/integration/decision-execution-contract-eligibility.test.ts) keeps those configured choices intact, proves all-unproven pools return no route with zero decision/execution calls, and proves a mixed pool can execute only its sole eligible original Claude pair. It does not measure live availability or selection quality.
