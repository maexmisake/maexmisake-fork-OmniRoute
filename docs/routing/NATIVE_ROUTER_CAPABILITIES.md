## Provider-native output: implemented, off by default

`applicationMode: "provider-native-output-v1"` is a separate stored opt-in. Its strict `nativeOutput` object requires `acknowledgeNoTokenCeiling: true` and an operator-chosen integer `contextOutputTokens` from 1 to 1,000,000. No planning allowance is selected automatically. The dashboard exposes the mode, visible no-ceiling disclosure, planning input and acknowledgement; the authenticated management API enforces the same contract. Saving never runs a provider or changes an existing combo unless explicitly submitted. Existing revisions, cancel/reload and disable recovery remain.

The caller must omit `max_tokens`, `max_completion_tokens` and unsupported cap aliases; even a cap equal to the planning allowance rejects before decision/execution. The mode accepts streaming text only. Tools, tool continuations, images, sampling controls and client-supplied activation are rejected. A client that supplies an output cap, including an ordinary Hermes configuration, must continue using bounded mode or explicitly change its own configuration; the router never silently removes that control.

The planning allowance is used for context eligibility and as the finite request maximum where a supported provider requires one. It is not a generation ceiling for native Codex or fixed AGY Opus. Native-mode responses disclose `x-omniroute-output-policy: provider-native` and `x-omniroute-output-limit-enforced: false`; these describe the router's mode-level guarantee, not an assertion that a provider with a finite request parameter ignores it. Timeout or clipped output does not bound remote generation.

## Native selection

The selector receives only currently eligible explicit model-and-effort options. A client-supplied effort is a hard constraint. For example, explicit Medium can offer both Opus Medium and Sonnet Medium; it does not authorize High or Max. Operator task preferences remain unchanged. Confidence is a provider-reported value, not measured correctness or permission.

Two or more eligible options use the configured native decision provider; exactly one uses the existing guarded execution with explicit `sole-eligible` / `no-decision`; zero returns `no-route`. Decision and execution receipts remain separate. Refusal, malformed selection, authentication/access/quota denial, cancellation and queued policy changes cannot authorize an unintended execution or hidden fallback.

Free Zen is treated as unavailable for this project at the operator's direction; its adapter remains optional, without any automatic paid replacement. This is not a universal service-availability claim. Free Zen requires an explicit native `jev-1.13-free` binding and the actual free routing guard. These local fixtures establish no live free-Zen success or quota-reset scope. Existing paid selector contracts remain separate; no paid fallback is introduced.
