# Native router completion and verification boundaries

This October 26 checkpoint keeps all 23 original model/effort choices and ordinary routing defaults. It adds guarded native-output function tools, local difficulty preferences, an operator receipt inspector and an offline evaluation preparation runner. No live account, provider or tool is invoked by these checks.

## Execution and continuation

Bounded mode still admits thirteen original tool pairs. Explicit `provider-native-output-v1` admits all 23 original pairs for declared flat function tools and authenticated continuations. Its acknowledgement and operator context-planning allowance remain mandatory. The twelve Claude pairs and Gemini High retain finite required wire limits using the allowance; the nine Codex pairs and fixed-thinking AGY Opus omit wire output caps, so the allowance is not a universal generation ceiling. Caller token caps and financially/token/schedule-capped keys reject rather than being silently changed. No profile, connection, entitlement or preference order is invented.

The actual installed-SDK suite has 68 passing cases, including all nine original Codex pairs, fixed AGY Opus High, Gemini High and representative Claude paths. Separate actual-handler synthetic fixtures cover all twelve Claude pairs; combined handler coverage retains all 23 original pairs. One initial native decision chooses an eligible pair; continuations retain its exact account/model/effort and require fresh admission. Each accepted request permits one execution, with no concealed execution fallback, recovery replay or paid substitution. Decision and execution usage remain separate. Native unknown cost remains unknown, including output exceeding the planning allowance.

Codex preserves original call IDs, arguments and private encrypted reasoning. Complete-transcript occurrence checks prevent a synthesized missing tool result. Indexed parallel calls may finish out of order; malformed, duplicate or altered replay rejects. Refusal, cancellation, committed output, changed policy and expired/missing authority do not authorize another call. Replay is bounded process memory, so restart/eviction may reject a continuation; it does not reconstruct remote execution.

Fixed AGY Opus High sends no invented High parameter, thinking budget or output cap. Its replay uses a separate `agy-opus-tool-parts-v1` envelope and preserves genuinely absent or present native IDs/signatures. Gemini's existing signature requirement remains. Generic source schemas support the carriers, not live private-Opus interoperability.

Namespaced, custom and provider-built-in tools are unsupported. AGY retains narrower schema, history, signature and parallel-control limits. Tools and continuations are not an unrestricted promise for every Hermes tool schema, retry, CLI integration or agent feature. Actual tools never run in the fixture. A third handcrafted handler turn tests deeper lineage separately from two-request SDK loops.

## Local selection and dashboard

[Local difficulty extraction](../../open-sse/services/decisionPolicy/taskDifficulty.ts) examines at most 16,384 UTF-16 code units of the accepted user task. Oversized, ambiguous and reference-only inputs remain unknown. Only fixed labels, counts, booleans and reason codes reach decision metadata; no new prompt excerpt is transmitted. Difficulty is an auditable heuristic, not calibrated correctness. Task intent and task difficulty remain distinct.

The structured profile editor can explicitly create and reorder `task:difficulty` preferences from the existing base order. Without a stored difficulty-specific key, the exact existing base order remains. Empty scoped orders remain genuine no-route outcomes. Difficulty never enlarges hard eligibility or overrides explicit client effort. Ordinary Hermes unset effort still defaults to Medium unless the separately documented, uninstalled effort-delegation extension is deliberately configured.

The dashboard's manual attempt inspector uses authenticated `GET /api/decision-routing/attempts`. It requires operator authority even when login is disabled; inference and delegated/admin API keys do not grant access. One bounded journal SELECT returns at most 100 rows with date/combo/keyset filters. It neither reconciles nor expires attempts and performs no provider probe. Authentication may retain ordinary bookkeeping. The browser receives sanitized stages, selected identity/effort, unknown-versus-zero usage/cost and observed lease state, excluding credentials, connection IDs, owner capabilities, private payloads and raw errors. Reload/pagination use cancellation and stale-response guards.

## Evaluation and evidence

The [evaluation runner](../../scripts/router-eval/decisionPolicyEvaluation.ts) preserves the original 23 IDs and effort levels and separates evaluator labels/oracles from selector inputs. Default preparation performs zero physical attempts. Synthetic callbacks test policy conformance, not model quality. Paired-result validation binds case/input/policy identities and preserves unrun/unknown/failure and nullable costs; imported responses and candidate implementations are not authenticated by a hash.

The existing 70 development and 30 exposed post-design synthetic cases are not an independent unseen benchmark. Preparation yields respectively 24/11 prepared text cases, 35/16 genuine no-route cases and 11/3 explicitly unrun cases. All 51 no-route cases have unresolved task preferences in the synthetic control; they are not provider incompatibility findings. Fourteen cases exceed this text-only runner's scope, not the application's new tool support. No preference was fabricated to make coverage appear complete. Historical rejected evaluation results remain unchanged.

Final selected verification: 2,278 Node tests across 100 files, 590 MCP Vitest tests and 34 dashboard component tests pass. Runtime/test/fixture hashes remained unchanged during the broad Node run; there were zero skips/cancellations. The first broad run's three stale contract expectations were retained as failures, corrected for the new tool contract, and the complete selection rerun passed. Core compilation passes. Strict core retains eighteen byte-identical release-baseline diagnostics; the expanded affected graph has 530 baseline and 530 current diagnostics with no introduced errors. Complexity limits were not raised. These overlapping scopes are not added into a quality score or a claim that the full repository suite passes.

The exact 6d9 runtime previously passed a 638-page PC production build, standalone boot and browser checks. That predates these runtime changes; this checkpoint needs its own compatible PC build/browser pass. A contained genuine pinned Hermes attempt stopped at native Relay attestation before any application/decision/execution request. Full-agent acceptance, live prototype interoperability, authentication/entitlement and independent selection quality remain unverified.
